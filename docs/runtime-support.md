# Runtime support: OG 1.10.163 and AE 1.11.x

**STATUS: PARTIAL.** The single `DynamicStringDistributor.dll` runs on OG 1.10.163 exactly as before. On AE 1.11.x (phase C) it runs **nine features**: base, activateText, leveledNames, constTranslation, miscTypes, bodyParts, prompts, runtimeText and dialogueOptions. Inside constTranslation the sparse FULL map group (names of STAT, MSTT, SCOL, KYWD, FLST, LIGH forms) is ON on AE since phase D2 (layout proven from the AE executables, guarded at run time; docs/phaseD-sparse-fullname.md). dialogueOptions is ON as well (phase D: vanilla wheel, plus the XDI path when XDI.dll is loaded; docs/phaseD-dialogue-options.md); nameRefresh is ON on AE since phase E (walk layout and engine calls proven in docs/phaseE-namerefresh-proof.md; the two engine functions it calls are byte-checked before each run; containers rebuild only names with Hangul). nameDiag stays OFF (its cell-attach event source is not analyzed; it is a debug log only). DSD does not patch other plugins; the optional `MenuRefCountFix.dll` (`plugins/MenuRefCountFix/`) patches a known non-atomic Scaleform menu AddRef in two other plugins. **NG (1.10.980 / 1.10.984) is not supported** (there is no NG column). In game: tested on OG 1.10.163 and AE 1.11.240; AE .191 and .221 never ran in game, so the status stays PARTIAL. Every ID an ON path reaches was checked in all six 1.11.x Address Library bins: `docs/phaseC-ae-id-audit.md`.

**Library defect that matters for every AE change:** `REL::IDDB::id2offset` used to return the offset of the next larger ID when an ID is missing. A fork wrapper with a wrong AE ID therefore ran the wrong function. The DSD patch now aborts the game with a message instead, but only after `F4SEPlugin_Load` has called `REL::IDDB::SetStrictLookup(true)`. Reason: six namespace-scope `inline REL::Relocation x{ REL::ID(n) }` globals in the fork (Workshop `CurrentPlacementItemData`, `CurrentRow`, `PlacementItem`; `ImageSpaceEffectTemporalAA::MaskS`; `ImageSpaceEffectPipboyScreen::bPowerArmorPipboy`; `CombatUtilities::fWorldGravity`) look up IDs absent from every 1.11.x bin while the DLL loads, before any DSD code runs; a strict patch alone would abort every AE start (found in phase C by `phaseC/impl/trace_dll.py`). DSD uses none of them. Until the plugin load callback a missing ID resolves to offset 0. See `ae-crosscheck.md`, "Library defects found in Phase B", and `phaseC-ae-id-audit.md`. DSD bypasses `TESForm::GetFormByID`, `TESDataHandler::GetSingleton`, `MemoryManager::GetSingleton` and `GameSettingCollection::GetSingleton` on AE (`src/Runtime.h`).

## Runtime detection and CommonLibF4 patch

`src/Runtime.h` classifies 1.10.163 as OG and every 1.11.x as AE. There is no exact-version whitelist; safety comes from the per-hook byte checks. All other versions are Unsupported. Query and Load both enforce this. `F4SEPlugin_Version` exports `addressIndependence = 0x4` and `structureIndependence = 0x4` (bit 2 only: F4SE 0.7.9 admits the plugin on 1.11.x; bit 1 is clear, so NG F4SE refuses it). Query stays exported for OG F4SE 0.6.23.

`cmake/patches/commonlibf4-runtime-detection.patch` changes upstream `Module::load_version` from comparing only the build component to comparing the complete version against `Version{1,10,980}`. The fork then picks its second ID slot (named NG in the fork) on every 1.11.x, which is the slot `REL::RelocationID(og, ae)` uses. CMake applies the patch before it configures the pinned submodule (forward apply, or skip when already applied, otherwise fail). The configured submodule is dirty by design; the reproducible change lives in the parent patch.

No IDDB format patch is needed. `REL/IDDB.cpp` builds `Data/F4SE/Plugins/version-<major>-<minor>-<build>-<revision>.bin`, and the supplied AE files have the expected layout.
